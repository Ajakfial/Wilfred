# iOS Build

Wilfred on iOS is a SwiftUI app over the same C++ core (`wilfred_core`)
used on desktop and Android. The app contains:

- **Swift UI** (`ios/Wilfred/`): `ContentView` (search bar + assist strip +
  results, same layout as Android's `MainActivity`), `ResultRow` (same row
  as Android's `row_result`), `WLogo` (same "W" artwork as `ic_w.xml`),
  `WilfredActions` (open/share/clipboard/menu logic), `WilfredCore`
  (bridge wrapper). Entry point is the app icon — iOS forbids
  overlay windows, so Android's floating "W" (`FloatingWService`) has no
  equivalent; the in-app UI is otherwise identical.
- **C++ core, compiled directly** (`Wilfred.xcodeproj`, generated by
  `scripts/generate-ios-project.py` from `CMakeLists.txt`): `MobileCore`
  (`include/wilfred/platform/android_bridge.hpp`, shared with Android)
  boots config/index/history/snippets/plugins/providers from the app
  sandbox documents dir and serves `search_json` / `assist_json` /
  `actions_json` / `execute_action` / `preview_json` / `status_json`.
  Opening (URLs via `UIApplication.open`, files via share sheet) happens in
  Swift from the result payload. The ObjC++ bridge
  (`WilfredCoreBridge.h/.mm`) is the only file that touches both worlds.
- **iOS platform backend** (`src/platform/ios/`): polling file watcher,
  null overlay (SwiftUI owns it), no-op hotkey (app-icon launch replaces
  it), iOS clipboard override (Swift pushes/pulls `UIPasteboard`; C++
  never forks `pbpaste`), sandbox-only volumes, explicit-error stubs for
  launch/browser/windows/screenshots/process/media.

## Requirements

- macOS with Xcode 15+ (iOS 17 SDK), Python 3 (project generator)
- Simulator builds need no signing; device builds need
  `WILFRED_APPLE_TEAM_ID`

## Build the app

```bash
./scripts/build-ios.sh --simulator            # unsigned, DerivedData .app
./scripts/build-ios.sh --simulator --debug
./scripts/build-ios.sh --device               # needs WILFRED_APPLE_TEAM_ID
```

Local version override (release CI sets these from the tag):

```bash
WILFRED_VERSION_NAME=1.2.3 WILFRED_VERSION_CODE=1002003 \
  ./scripts/build-ios.sh --simulator
```

`build-ios.sh` regenerates `ios/Wilfred.xcodeproj` first via
`scripts/generate-ios-project.py` (parses `WILFRED_CORE_SOURCES` + the
`elseif(IOS)` backend block from `CMakeLists.txt` and scans
`ios/Wilfred`), so the project can never drift from the CMake build.
`--check` validates without writing.

## Behavior notes

- Search, fuzzy/rank/filters, calculator/convert, macros, quicklinks,
  snippets (+`{clipboard}`/`{date}` expansion), notes/todos, timers,
  clipboard history, content/OCR/semantic providers, and ranking all run in
  C++; results cross the bridge as JSON
  (`{title,subtitle,path,payload,score,action,category,kind,actions:[{id,label}]}`).
- Assist crosses as `{"correction":"","ghost":"","candidates":[]}` for
  "did you mean", ghost completion and the candidate strip.
- `http(s)` payloads open via `UIApplication.open`; sandbox files open in
  a share sheet; calc/convert/copy/snippet cards copy to `UIPasteboard`.
- Long-press (or context menu) shows the full C++ action list
  (`actions_json`) and runs side-effect actions via `execute_action`
  (timer stop, note/todo delete, clip pin/clear, copy flavors, hash,
  workflows/layouts).
- File peek uses `preview_json` (exists/is_dir/size/text head).
- `wifi` / `bluetooth` / `settings` cards open the Settings app (the only
  settings entry point Apple allows third-party apps); `volume` /
  `brightness` cards explain that the side buttons / Control Center own
  them on iOS. `config` / `setup` / `plugins` cards run through C++
  against the sandbox `wilfred.yml` and trust store.
- Window management, tiling, global hotkeys, screenshots, app launching,
  and process/media control are desktop-only (or Android-only) and report
  explicit messages on iOS. iOS exposes no installed-app list, so
  `register_app` is never called and there are no `package:` results.

## Release builds (CI)

`.github/workflows/release.yml` has an `ios` job (macOS runner, Xcode,
simulator SDK) that runs on every `v*.*.*` tag, in parallel with the
desktop matrix and the Android job:

- Derives `MARKETING_VERSION`/`CURRENT_PROJECT_VERSION` from the tag
  (`v1.2.3` → `1.2.3` / `1002003`) and builds the unsigned simulator
  `.app` via `scripts/build-ios.sh --simulator` (`CODE_SIGNING_ALLOWED=NO`,
  so no Apple Developer secrets are needed and the job stays green).
- Zips it as `dist/wilfred-<tag>-ios-unsigned.zip` and uploads it as the
  `wilfred-<tag>-ios` artifact; the `release` job attaches `*.zip`
  archives alongside the desktop and Android artifacts.

Device/IPA distribution (TestFlight, App Store) needs Apple Developer
signing and is a manual follow-up: build with `--device` plus
`WILFRED_APPLE_TEAM_ID`, then archive/export from Xcode.
